## What a footprinter string is

A `footprint` prop is a compact string that footprinter (`@tscircuit/footprinter`) expands
into a pad layout. Pass the string, not a footprint object:

```tsx
<resistor name="R1" resistance="330" footprint="0603" />
<chip name="U1" footprint="soic8" />
<pinheader name="J2" pinCount={6} footprint="pinrow2_p2.54mm" />
```

## Passives

`0402`, `0603`, `0805`, `1206`, `1210` for chip resistors and capacitors. `0603` is the
safe default for hand-solderable hobby work: large enough to probe, small enough to fit.

## Packages

`soic8`, `soic14`, `soic16`, `sot23`, `sot223`, `to220`, `qfp32`, `qfn32`, `dip8`. ICs are
`<chip>`; pass the footprint as a string and set `pinLabels` so the pins can be named.

## Connectors and headers

`pinrow2_p2.54mm` is a two-row 2.54 mm header — the value is the number of pins. A 6-pin
2.54 mm header is `pinrow6_p2.54mm`. A 2.54 mm screw terminal is `screw_terminal_01x02`.

## A string that does not exist fails the compile

There is no validation step: an unrecognised footprinter string is a compile error, not a
warning. Use one of the forms above rather than inventing a package name.

## Where footprints come from at run time

Footprint strings that are not built into footprinter are fetched from the tscircuit CDN. The
compile sandbox disables that (`disableCdnLoading`) and stubs `fetch`, so **only the
built-in strings work here**. A design that needs a vendor-specific footprint cannot be
generated by this app; it is listed in docs/DECISIONS.md as a known limitation.
