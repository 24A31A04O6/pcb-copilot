# pcb-copilot

Describe a circuit in plain English. Get a tscircuit design that **compiles**, **passes its
fabrication checks**, and **exports as real manufacturing files** — or does not, and says
why.

```bash
pnpm install
cp .env.example .env.local     # add your FIREWORKS_API_KEY
pnpm run dev
```

Without a key the app runs, the health endpoint answers `degraded`, and every model-dependent
path refuses with a typed error. Nothing is faked.

---

## What it does

1. **Reads the brief.** Plain English becomes a validated JSON brief through
   `json_schema` on the wire *and* in the prompt.
2. **Retrieves the real API.** Before writing code, it looks up the tscircuit props for the
   version it is actually running. 156 chunks extracted from the installed
   `@tscircuit/props`, ranked with BM25 and an identifier boost, so `maxResistance` and
   `resistance` do not get confused.
3. **Writes tscircuit TSX.** One self-contained module, no imports, no network.
4. **Compiles it for real.** In an isolated child process with a wall clock, a memory cap,
   and a static safety pass over the source first.
5. **Checks it.** Connectivity, fab capability, decoupling, placement, silkscreen — against
   a *named* fabrication preset with a source URL and the date it was checked.
6. **Repairs it.** Up to three focused attempts, each given the exact findings from the last
   one.
7. **Only then unlocks exports.** Gerbers, Excellon, BOM, pick-and-place, a manifest and a
   README, zipped. If a blocking check fails, the API refuses — the button being greyed out
   is a courtesy, not the control.

## What it will not do

- Invent a manufacturer part number. There is an optional catalogue tool; when it is not
  configured, the design says so in plain language rather than implying the parts were
  verified.
- Pass a two-terminal part with a leg in the void. tscircuit does; this app does not.
- Report a model case as passing when it was skipped. `skipped` with a reason, always.

## Commands

| Command | What it does |
| --- | --- |
| `pnpm run dev` | Development server |
| `pnpm run build` / `pnpm start` | Production build and server |
| `pnpm run check` | typecheck → lint → test → build |
| `pnpm run test` | Unit and integration (225 tests) |
| `GOLDEN=1 pnpm run test:golden` | Compile and hash 23 golden designs |
| `pnpm run eval` | 24 offline eval cases; model cases report `skipped` |
| `pnpm run eval -- --model` | Add the 16 model cases (needs a key) |
| `pnpm run eval -- --compare` | Every case against both models → `docs/MODEL-COMPARISON.md` |
| `pnpm run eval -- --compare --only=a,b --budget=150000` | A named subset, with a hard token cap |
| `pnpm run golden:hash` | Regenerate golden hashes and print drift |
| `pnpm run test:e2e` | Playwright, axe, visual regression |
| `pnpm run verify:secrets` | Fail if a secret is committed |
| `pnpm run knowledge:build` | Rebuild the retrieval index from installed sources |
| `pnpm run build:assets` | Regenerate icons, OG image and the mascot sheet |

## Configuration

Every variable is documented in [`.env.example`](.env.example) with its range, its default,
and what goes wrong when it is wrong. The only required one is `FIREWORKS_API_KEY`.

There is deliberately **no `NEXT_PUBLIC_` variable**. Nothing the browser needs is
configurable, and nothing server-side is reachable from it.

`pnpm run eval -- --model` and `--compare` read the key from `.env.local` — the same file the
app reads it from — so the same secret serves both without being exported into a shell
history. `--budget=<n>` is a hard circuit breaker checked *before* each model case, sized
against the 8k output ceiling, so a run that would overspend stops instead of finding out
afterwards.

## Keyboard

`Cmd/Ctrl-K` opens the command palette; `?` opens it too. Every action in the app is in
there, and every one of them is reachable from the keyboard.
